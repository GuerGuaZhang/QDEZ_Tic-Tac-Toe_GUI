# 《二中棋》逆向报告

> 对象：`二中棋.exe`（同学制作的 3x3 三子棋小游戏，Windows x64 控制台程序）
> 编译：MinGW GCC 4.9.2（O2），带 COFF 符号 + DWARF 调试信息，字符串为 GBK 编码
> 本报告基于 `reverse/` 工具链产出的反汇编与字符串引用逐指令核对得出。

---

## 1. 可执行文件结构

| 节 | 说明 |
|---|---|
| `.text` | 代码段（RVA 0x1000 起，约 474KB） |
| `.data` / `.rdata` | 全局变量 / 只读数据（**中文文案为 GBK 编码**，位于 RVA 0x8B000 起） |
| `.pdata` | **RUNTIME_FUNCTION 表**：精确记录每个函数的 `Begin/End/UnwindInfo`——函数定位的最可靠来源（2517 条） |
| `COFF 符号表` | PE 文件尾部内嵌（`PointerToSymbolTable`/`NumberOfSymbols`），含全部函数符号（13790 条） |

关键：**COFF 符号地址即函数真实起点**（与 .pdata 一致），之前 `disasm.py` 的旧 START 表（main 0x4690、AI 0x32C0、game 0x3B00）是从数据区误定位，已修正。

## 2. 关键函数边界（来自 .pdata）

| 函数 | 符号 | 起点 | 结束 | 大小 | 职责 |
|---|---|---|---|---|---|
| `main` | `main` | 0x46E1 | 0x4719 | 56B | `__main()` → `srand(time(0))` → `while (home());` |
| `home` | `_Z4homev` | 0x19DE | 0x1D7C | 926B | 主菜单 + 退出确认 + 模式选择 |
| `hint` | `_Z4hintv` | 0x1D7C | 0x2330 | 1460B | 分页剧情（11 页） |
| `win` | `_Z3winv` | 0x24B7 | 0x28A8 | 1009B | 胜负判定（写结果到 0x4AB0EC） |
| `event` | （匿名） | 0x28A8 | 0x319D | 2293B | **随机事件 + 神秘事件彩蛋**（无符号名） |
| `player1` | `_Z7player1v` | 0x319D | 0x321C | 127B | 回合/输入有效性判定（返回 0/1） |
| `puthint` | `_Z7puthintv` | 0x321C | 0x32DF | 195B | 打印落子提示行 |
| `AI` | `_Z2AIi` | 0x32DF | 0x3B7A | 2203B | 人机落子（5 层策略） |
| `game` | `_Z4gamei` | 0x3B7A | 0x46E1 | 2919B | 对局主循环 + 结算 |

`0x401675`（settings，home 内）、`0x402330`（cls 封装）为辅助函数。

## 3. 关键全局变量（RVA 基址 0xAB0E0 起的连续区）

| 地址 | 含义 |
|---|---|
| 0x4AB0E4 / 0x4AB0E8 | 光标行 / 列（1..3） |
| 0x4AB0EC | win 结果（0/1/-1/2） |
| 0x4AB0F8 | 当前玩家/先手（1=○ 玩家, -1=× 人机；双人模式 0） |
| 0x4AB0FC | 神秘事件计数 |
| 0x4AB100 | `event_type`（每手随机 1..12） |
| 0x4AB104 / 0x4AB108 | 事件临时行 / 列 |
| 0x4AB074 起 | board（3x3 int 数组，落子值 1/-1） |

## 4. 随机事件机制（event 函数，每手落子后触发一次）

```
event_type = rand() % 12 + 1        // magic 0x2AAAAAAB 是 ÷12
```
| type | 概率 | 事件 | 细节 |
|---|---|---|---|
| 1–4 | 4/12 ≈ 33% | 消除格子(r,c) | r=rand()%3+1, c=rand()%3+1 |
| 5 | 1/12 ≈ 8% | 消除第 r 行 | r=rand()%3+1 |
| 6 | 1/12 ≈ 8% | 消除第 c 列 | |
| 7 | 1/12 ≈ 8% | 消除左上→右下对角线 | |
| 8 | 1/12 ≈ 8% | 消除右上→左下对角线 | |
| 9 | 1/12 ≈ 8% | 帮你下一手 | 随机空格放**当前玩家**的子 |
| 10 | 1/12 ≈ 8% | 反转局势 | 内部再 `rand()&1`：1→全盘取反+**玩家取反**；0→无事发生 |
| 11–12 | 2/12 ≈ 17% | 神秘事件 | `mystery_count += 1` |

神秘事件流程：`mystery_count < 5` → 仅打印 `神秘事件×N！！！`；`== 5` → 彩蛋：
`system("color 4F")` → 打印 → 计数清零 → `system("5次神秘事件凑齐了……")` → 构造并输出 `Windows的数据遭受了毁灭性的打击！！！` → `Sleep(speed×1000)` → **500 次循环变色** `color 2C/AE/7A/E4/58/B6` → `color 4F` → **MessageBox×3**（标题 `Windows系统自动提示`：警告/错误/警告）→ 输出 `数据已被破坏……请重新开始……` → `Sleep` → `player = -1` → `color 07` 恢复。

## 5. 人机 AI 策略（5 层，非随机启发式）

1. **赢**：行/列/双对角任一线 2 子 → 补第 3 格
2. **挡**：同上逻辑挡玩家（sum == -player×2）
3. **中心**：中心空则下 (2,2)
4. **线扩展**：对角/行已有 1 个己方子且无威胁 → 优先占位发展该线
5. **兜底**：按**固定顺序**扫描 9 格选第一个空（顺序 4,6,10,12,5,7,9,11 线性索引），**非随机**

board 为全局一维数组，返回线性索引（3i+1/3i+2/3i+3 等）。

## 6. 速度档位语义

`Sleep(speed × N)`，N 随落子位置不同：
- 中心 (2,2)：`×100` ms
- 角/边（row+col==3 或 5）：`×50` ms（两次）
- 其他：`×0.5`（double）
- 彩蛋：`×1000` ms

（GUI 复刻用统一 `250×speed` 为简化近似。）

## 7. 输入机制

- 主菜单/模式选择/设置：**GetAsyncKeyState 轮询**（非阻塞），键位 `P`(设置) `S`(开始) `H`(说明) `E`(退出) `A/B/C`(模式)，设置页上下/左右键 + `E` 退出
- 对局：**双输入组同时轮询**——`wsad`+空格 与 方向键+`Enter`，由 `player1` 判定生效（键盘偏好设置仅单人模式有效）
- 退出彩蛋：主菜单 `E` → `确定要离开吗？/是 y/否 n` → 选 y → `cls` → `system("qwq")` → 退出

## 8. 对局主循环（game）

```
board 清零(memset 100B) → 光标 (2,2)
loop:
  当前玩家==人机 ? "人机计算中……" : puthint 打印"现在轮到%s（执%s）了，你要下在哪一行，哪一列？%s"
  轮询输入 → player1 判定 → 移动光标/落子
  落子: board[r][c]=player → Sleep(分位置) → win 检查
  win==0 → event(当前玩家) → win 检查
  win==0 → 玩家取反 → 回到 loop
win!=0 → "要再玩一局吗？" → 是: 重开; 否: 结算（正在计算最终得分……→ 最终的胜利者是：%s！/最终结果是……平局！→ 你们的比分为：%d:%d。→ 欢迎下次再玩！）
```

## 10. 工具链

| 脚本 | 用途 |
|---|---|
| `parse_coff.py` | 从 exe 尾部解析 COFF 符号表（自包含，无外部依赖） |
| `pdata.py` | 解析 .pdata RUNTIME_FUNCTION 精确枚举函数边界 |
| `disasm.py` | 按函数边界反汇编输出 `dis_*.asm.txt` |
| `entry.py` | 反汇编入口 0x1500 附近 |
| `find_start.py` | prologue 启发式定位（**有假阳性，已被 pdata.py 取代**，保留备查） |
| `xref.py` | 全量反汇编 + 字符串引用（GBK 解码中文）+ 调用图 |
| `extract_strings.py` | 提取 .rdata/.data 字符串 |

## 11. 遗留问题

- `extract_strings.py` 的 UTF-16 提取为噪声（中文实为 GBK），中文证据以 `xref_strings.txt` 为准
- 字符串 RIP 目标在部分 lea 指令上存在 0x28800 偏移（疑似节基址换算差异），以 `xref_strings.txt` 实测记录为准
- `0x401675`（设置）完整键位分支未逐条展开；`hint` 剧情跳过的 P.S.（Enter/空格）逻辑未细究
